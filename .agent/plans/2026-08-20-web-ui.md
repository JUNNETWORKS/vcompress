# Local WebUI and observable compression jobs

## Purpose and big picture

Someone running `vcompress` will be able to start `vcompress web`, choose a
server-side directory in a browser, configure the same compression policy as
the command line, and watch one sequential compression job through discovery,
quality analysis, final encoding, validation and publication. The page will
show the number of candidate files, the current file and phase, final-encode
percentage and estimated time remaining, aggregate counts, logs and per-file
results. It will offer an immediate cancellation and a graceful stop after the
current file. Closing or reloading the browser will not stop the job.

The existing `vcompress [options] DIRECTORY` interface and every media-safety
gate remain in force. The WebUI is an optional localhost controller around the
same application service; it does not replace `internal/processor` or create a
second compression implementation. This change does not expose the server to
the local network, add authentication, persist job history, upload media,
queue jobs, run encodes in parallel, create a native desktop application or
roll back already published files.

## Context and orientation

`cmd/vcompress/main.go` currently owns command-line parsing, executable and
directory checks, NVIDIA capability probes, selector construction, recursive
discovery, per-file processing, logging, signal handling and final counters in
one `run` function. `internal/config/config.go` defines the complete compression
configuration and its validation. `internal/discovery/discovery.go` walks the
directory and invokes a callback as each video-looking path is discovered, so
the total is not known before processing begins.

`internal/processor/processor.go` is the safety-critical per-file orchestrator.
It probes input metadata, applies codec and High Dynamic Range (HDR) skip rules,
selects a quality value, writes to a same-directory temporary file, validates
structure and a full decode, checks minimum savings and only then publishes or
atomically replaces the source. An atomic replacement is a filesystem operation
that makes the complete validated file visible at once rather than exposing a
partially written file. This plan adds observation hooks around those steps and
an explicit cancellation check before publication; it does not relax any skip,
validation, savings or replacement rule.

`internal/quality/selector.go` tries encoder-specific quality values 20, 18 and
16 against representative samples. VMAF (Video Multi-Method Assessment Fusion)
and SSIM (Structural Similarity Index Measure) are decoded-image comparison
metrics used to reject an output whose samples fall below configured thresholds.
The selector logs each sample but does not publish typed progress.

`internal/ffmpeg/client.go` builds FFmpeg and ffprobe commands.
`internal/ffmpeg/runner.go` currently buffers stdout and stderr until a child
process exits. FFmpeg's `-progress pipe:1` option instead emits machine-readable
`key=value` records to standard output, including `out_time_us` and `progress`.
The final encode will consume those records while retaining stderr for failure
diagnostics. A Server-Sent Events (SSE) response is a long-lived HTTP response
whose `data:` records let a server push one-way updates to a browser and whose
browser client reconnects automatically.

`internal/logging/logging.go` writes timestamped lines to both the console and
`ffmpeg-compress.log`. The Web job will pass a writer that retains a bounded
copy for the page while the file logger continues to be authoritative.

The implementation adds `internal/progress/` for package-neutral event types,
`internal/job/` for the shared batch application service, and `internal/webui/`
for single-job state, HTTP handlers, embedded browser assets and browser launch.
The browser assets live under `internal/webui/static/` and are embedded with
Go's `embed` package. No JavaScript build step, Node.js runtime, framework or
new Go module dependency is introduced.

## Interfaces and dependencies

`internal/progress/progress.go` will define a `Phase` string with discovery,
probe, quality, encode, validation and publication values. Its `Event` includes
the input path, phase, quality candidate, sample position and count, encoded
media time, total duration, percentage, estimated remaining duration and a
human-readable message. A `Reporter` interface exposes
`Report(progress.Event)`, with a function adapter and a no-op-safe helper.

`internal/discovery/discovery.go` will add:

```go
func List(root string) ([]string, error)
```

It uses the same `Walk` and `IsVideoPath` rules and returns paths in filesystem
walk order. The batch service calls `List` before starting a file, so the page
can report an exact extension-based candidate count. Codec and HDR eligibility
remain processing-time decisions.

`internal/ffmpeg/runner.go` will add a `ProgressRunner` optional interface:

```go
type ProgressRunner interface {
    RunProgress(context.Context, string, func(string, string), ...string) ([]byte, []byte, error)
}
```

`OSRunner` implements it with `exec.CommandContext`, a stdout pipe, a scanner
for `key=value` records and a buffered stderr. Test runners that only implement
the existing `Runner` remain valid; the client falls back to buffered `Run` and
still completes without live updates.

`internal/ffmpeg/client.go` adds `Duration float64` and
`Progress func(EncodeProgress)` to `EncodeOptions`. `EncodeProgress` contains
processed duration, total duration, percent, speed and estimated remaining
time. Final encode arguments add `-nostats -progress pipe:1`. `out_time_us` is
interpreted as microseconds, percentage is clamped to 0 through 100, and ETA is
calculated from wall-clock elapsed time only after positive progress. The
existing NVIDIA decode-to-encode retry remains the single fallback path; every
attempt can report progress.

`internal/quality/selector.go` adds an optional `progress.Reporter` field to
`Selector`. Before each measured sample it reports the candidate quality,
one-based sample index and sample count. Direct CRF (Constant Rate Factor) and
NVENC CQ (constant-quality) selection emit no measured-sample events because
those modes intentionally skip analysis.

`internal/processor/processor.go` adds an optional `progress.Reporter` field.
It reports phase changes immediately before probe, quality selection, encode,
validation and publication, and forwards final-encode updates. `Result` gains
the source path, output path, reason, original bytes and output bytes needed by
the result table. Existing status constants remain compatible and a cancelled
status is added. Immediately before metadata copying and publication,
`Process` checks `ctx.Err()`; cancellation therefore removes the deferred
temporary output rather than publishing it. Once `ReplaceFile` or `os.Rename`
has started, the atomic filesystem operation is allowed to complete.

`internal/job/job.go` exposes a shared application service:

```go
type Options struct {
    Console          io.Writer
    Reporter         progress.Reporter
    StopAfterCurrent func() bool
    OnResult         func(processor.Result)
}

type Summary struct {
    Total, Processed, Converted, Skipped, Failed int
    SavedBytes int64
    StartedAt, FinishedAt time.Time
    Interrupted, Stopped bool
}

func Run(context.Context, config.Config, Options) (Summary, error)
```

The service performs the current executable checks, logger creation, FFmpeg
feature and NVIDIA probes, selector construction, startup logging, discovery,
sequential processing and final logging. It checks `StopAfterCurrent` before
starting every next candidate. The command line maps invalid setup or failed
files to exit 1 and signal cancellation to exit 130, preserving current
semantics.

`internal/webui/manager.go` owns one mutex-protected snapshot, one cancel
function, one graceful-stop flag and SSE subscribers. POST `/api/jobs` accepts
a JSON representation of `config.Config`, normalizes and validates it, rejects
an active second job with HTTP 409, and starts `job.Run` in one goroutine. GET
`/api/state` returns the complete in-memory snapshot used after page reload.
GET `/api/events` streams snapshot changes as SSE. POST `/api/jobs/stop`
accepts `{"mode":"now"}` or `{"mode":"after-current"}`. Logs are bounded to
the newest 500 lines to prevent unbounded memory growth; the on-disk log is not
truncated.

GET `/api/defaults` returns `config.Default()`. GET `/api/directories?path=...`
returns only directory entries plus a parent path. An empty path begins at `/`
on Unix and the current working directory's volume root on Windows. Direct path
input remains available for other Windows volumes. POST handlers require
`Content-Type: application/json` and reject a non-empty `Origin` whose host does
not match the request host.

`internal/webui/server.go` always listens on `127.0.0.1`. `vcompress web`
accepts `--port` with default 8080 and `--no-open`. A busy port returns a clear
error instead of silently choosing another address. Unless disabled, the URL is
opened with `open` on macOS, `rundll32 url.dll,FileProtocolHandler` on Windows,
or `xdg-open` on Linux. Failure to open a browser is logged but does not stop
the server.

The embedded frontend uses semantic HTML, responsive CSS and browser-native
JavaScript only. It fetches defaults and state, submits jobs, connects with
`EventSource`, displays phase and progress bars, calculates human-readable
durations, browses directories, exposes advanced fields in `details`, asks for
confirmation before disabling full decode or stopping immediately, and filters
the per-file table by all, skipped or failed.

## Plan of work

First create the neutral progress types and discovery list operation with unit
tests. Then add FFmpeg streaming support and progress parsing behind an optional
runner interface, proving argument construction, parsing, cancellation and the
buffered test-runner fallback without needing a GPU. These contracts must exist
before the processor can report meaningful phases.

Next add typed observation to quality and processor while keeping all safety
decisions and filesystem calls in their current order. Focused tests will prove
phase ordering, measured sample reporting, rich results and cancellation before
publication. The source-preservation tests remain unchanged evidence that the
new hooks cannot bypass validation.

Then extract the batch-level setup and loop from `cmd/vcompress/main.go` into
`internal/job/job.go`. The command-line entry point will use an explicit
`flag.FlagSet` and dispatch only when the first argument is exactly `web`, so
all existing flags and positional directory syntax retain their meaning.
Application-service tests will cover pre-discovery counts, sequential results,
graceful stop and cancellation.

After the shared service passes, implement the mutex-protected manager and HTTP
surface using `net/http` and `httptest`. Only then add the embedded HTML, CSS and
JavaScript, because the page should consume tested JSON contracts rather than
define them accidentally. Add browser-open command selection tests that do not
launch applications.

Finally document usage, build the host and Windows binaries, run all tests and
vet, run the real libx265 integration suite, and exercise a disposable generated
video through both the legacy CLI and Web HTTP API. Render or open the page in a
local browser, inspect idle, running and completed states, and update this plan's
Progress, Surprises, Decision log, Artifacts and Outcomes with observed evidence.

## Idempotence and recovery

Formatting, unit tests, vet, builds and HTTP dry runs are repeatable. Starting a
second server on the same port fails without modifying state. Repeated dry-run
jobs perform no encode or publication. A non-dry job still writes only a unique
same-directory `.<name>.ffmpeg-compressing-*` temporary path, and
`Processor.Process` defers its removal. Immediate cancellation terminates the
child process through its context and removes that temporary path. A graceful
stop finishes the current file through existing validation and publication and
does not begin another.

Use only disposable generated fixtures for observable tests. Existing final
destinations are skipped rather than overwritten. To undo code work, revert the
explicit files changed on `codex/web-ui`; do not reset or clean a worktree that
may contain unrelated user changes. The Web state is memory-only, so restarting
the process returns it to idle without a migration or database cleanup.

## Surprises and discoveries

The `gh` command-line credential for `JUNNETWORKS` is invalid, but the connected
GitHub application successfully read and updated Issue #8. The unchanged
`mise run check` initially failed because the managed sandbox could not read the
Go build cache under the user's Library directory. Running the equivalent
`go test ./...` and `go vet ./...` with approved cache access passed.

The first full-page browser screenshot showed that the stop controls and direct
quality input were visible while idle even though their elements had the HTML
`hidden` attribute. Author CSS rules such as `.stop-controls { display: flex; }`
overrode the browser's built-in hidden rule. Adding `[hidden] { display: none
!important; }` restored the intended state; browser inspection then reported
`stopVisible: false`, `qualityValueVisible: false`, and `metricVisible: true`.

The generated 12-second 1280x720 MPEG-4 fixture produced a CRF 24 HEVC temporary
output that was slightly larger than its source (`2.0 MiB -> 2.1 MiB`). This was
useful safety evidence rather than a test failure: the existing savings gate
reported `output is not smaller`, removed the temporary file and retained the
source.

## Decision log

2026-08-20 — JUNNETWORKS and Codex: Use one optional Web mode in the existing
binary, automatically open a browser, and retain the legacy CLI unchanged. A
separate desktop application or Web binary would multiply release artifacts and
cross-platform maintenance without improving the compression core.

2026-08-20 — JUNNETWORKS and Codex: Bind only to `127.0.0.1`, run one in-memory
job and one sequential file at a time, and defer authentication, LAN access,
queues and persistence. This preserves the current resource and security model.

2026-08-20 — JUNNETWORKS and Codex: Use Go `net/http`, embedded vanilla browser
assets, JSON APIs and SSE with no external dependencies. Progress is server-to-
browser only, so SSE provides reconnect behaviour without WebSocket complexity
or a JavaScript build toolchain.

2026-08-20 — JUNNETWORKS and Codex: Pre-list extension candidates but retain
codec and HDR decisions at processing time. Pre-probing every file would delay
start and still require a fresh safety probe if files changed before encoding.

2026-08-20 — JUNNETWORKS and Codex: Provide both immediate cancellation and a
graceful stop. Immediate cancellation discards unvalidated temporary output;
graceful stop avoids wasting a nearly complete encode. Neither rolls back files
that already completed safe publication.

2026-08-20 — Codex: Default to port 8080 and fail clearly if it is busy rather
than silently moving. A stable printed URL is easier to reopen and automate;
`--port` resolves local conflicts explicitly.

2026-08-20 — Codex: Bound browser-visible logs to the newest 500 lines while
leaving `ffmpeg-compress.log` append-only on disk. Full unbounded logs in every
SSE snapshot would grow memory and local transfer costs during long batches.
